# 영상 변환 품질 전용 스킬

1. 원본 이미지를 먼저 본다. 피사체, 빈 이동 경로, 전경·중경·원경, 고정 구조, 광원을 적는다.
2. [변환 원칙과 템플릿](references/prompt-engineering.md)을 읽고 이미지에서 가능한 이동으로 프롬프트를 작성한다.
3. [원문 아카이브](references/original-prompts.md)는 과거 사용/준비 프롬프트의 기록이다. 성공 보증 템플릿으로 취급하지 않는다. 제출 증거가 없는 항목은 준비본이다.
4. [품질 체크리스트](references/quality-checklist.md)로 시작·중간·끝과 전체 재생을 검사한다. 실패는 한 요소씩 수정한다.
5. 사용자 속도 요구를 유지하면서 동시에 변해야 할 대상 수를 줄인다. 모델 이름이나 해상도로 품질 개선을 단정하지 않는다.

## 이 프로젝트의 고정 제약
말하는 정면 얼굴, 게임 HUD, 반복적인 아바타 양팔 시점 금지. 필요한 손/옷자락/작은 뒷모습만 사용. 로마 새 H3 요청은 minimax/minimax-h3, resolution=768p 명시. 480p는 무료 확인 해상도가 아니다. 매 제출 직전 동일 전체 요청의 견적 두 번 모두 discountCost=0, discountCredit=0, activityMode=unlimited여야 한다. 유료 재생성/업스케일 금지. 이 스킬을 읽었다고 제출 승인이 새로 생기지는 않는다.

## 품질 판단의 범위
이번 패키지는 기존 프롬프트와 검수 기록을 분석한 개선안이다. 새·옛 세션 전체 영상을 동일 조건으로 비교 평가한 실험 결과는 아니다. 아래 원칙은 제작 제안이며 결과 검수가 필요하다. 전체 decode 통과는 시각적 품질 합격과 다르다.
