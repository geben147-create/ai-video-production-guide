# 배분·프로젝트 프로필·이전

## 무엇을 70%로 세는가

기본은 편집 계획의 장면 수다. 생성 모델이 70개라는 뜻도, 전체 생성 요청을 70회로 제한한다는 뜻도 아니다. 사용자가 말한 '약 70개'는 연결된 100장면 계획의 맥락에서 해석했다.

| 지표 | 계산 | 주의 |
|---|---|---|
| 영상 장면 비율 | AI 영상 장면 수 / 전체 장면 수 | 기본 목표 약 0.70 |
| 영상 시간 비율 | AI 영상 장면 초수 합 / 전체 초수 | 장면 길이가 다르면 위와 다름 |
| 최소 생성 단위 | 장면별 필요한 소스 클립 수 합 | 순차 5초 두 개면 2단위 |
| 실제 제출 수 | 요청 로그의 고유 작업 수 | 재시도·실패·대안까지 별도 집계 |
| 채택 수 | 최종 편집에 실제 사용한 결과 수 | 계획·성공 상태와 구분 |

새 프로젝트에서는 먼저 대본으로 시간 순서를 만든다. 총길이의 마지막 1/3 부근에 image_eligible_from_seconds를 정하고 앞부분·핵심 하이라이트를 영상으로 보호한다. 보호 장면을 지정한 뒤 뒤쪽 설명·비교·자료·여운을 사진 모션으로 배분한다. 비율 때문에 대본을 늘리거나 줄이지 않는다. 서로 다른 길이의 장면은 시작 시각으로 배치하되 경계에 걸친 중요한 행동은 온전히 영상으로 둔다.

후반에 행동과 스펙터클이 많아 영상 78%가 필요하면 이유를 기록하고 보호한다. 30% 사진을 채우기 위해 초반을 정지 사진으로 바꾸지 않는다. 이미 승인된 계획은 계산상 이상적인 비율보다 우선한다. 짧은 예고편도 자동으로 100장면으로 늘리지 않으며, 재사용 가능한 본편 자산이 있으면 우선 검토한다.

## 범용 예시

assets/example-plan-100.json: 100장면 × 5초 = 500초. 001–067은 영상, 후반 070·084·098을 하이라이트 영상으로 지정한다. 합계 영상 70 / 사진 모션 30 / 최소 생성 단위 70이다. 이는 새 배분을 설명하는 예시이며, 입력 파일은 없고 상태는 planned다. 실제 주제와 하이라이트를 대입한 뒤 사용한다.

## 기존 로테르담 예시를 보존하는 방법

사용자가 제공한 cinematic-rank1/plan.json을 2026-09-09 읽어 확인한 값이다. 이 프로필은 해당 작품을 다시 열 때만 선택한다. 범용 기본 조건으로 확산하지 않는다.

| 항목 | 기존 계획 |
|---|---|
| 장면 | 100 |
| 초중반 영상 | 001–066 |
| 후반 보호 영상 | 068·070·071·081·093·097 |
| 영상 / 사진 모션 | 72 / 28 |
| 길이 | 510초 |
| 장면 023 | 10초 영상, 순차 5초 단위 2개 |
| 장면 100 | 10초 사진 모션 |
| 총 최소 생성 단위 | 73 |
| 영상 / 사진 시간 | 365초 / 145초 |
| 영상 장면 / 시간 비율 | 72% / 약 71.57% |
| 첫 사진 시작 | 335초 |

첫 사진이 정확히 2/3인 340초보다 5초 앞선다. 기존 승인 계획의 장면 경계이므로 340초 고정 규칙으로 덮어쓰지 않는다. 기존 모델 배치, 무료 확인, 작업 ID, 재생성 금지, 순차 진행, 일시정지 상태는 해당 프로젝트의 원본 기록에서 다시 읽는다. 이 범용 스킬이나 위 표만으로 제작을 재개하지 않는다.

## 기존 JSON을 v2로 옮길 때

1. 원본은 보존하고 사본에 version 2.0, topic, policy의 총길이·프레임률·기본 생성 초수·사진 허용 시작·목표 장면 비율·보호 장면 ID를 넣는다. 총길이와 시작 시각은 원본을 이용한다.
2. frame_id는 보존한다. 각 행에 purpose, highlight, start_seconds, duration_seconds, generation_units, source_image, status, transition을 매핑한다. 아직 없는 소스는 null 또는 빈 문자열로 기록하고 approved라고 표시하지 않는다.
3. 사진 행에 motion_recipe, source_ids를 넣는다. 기존 작업·해시·검수 기록 등 추가 필드는 유지 가능하다. 기존 ID의 중복 제출은 별도 실행 로그와 대조한다.
4. 생성 단위는 계획상 최소 소스 수다. 실제 모델에 추가 핸들이 필요하면 그 수를 올리고 사유를 기록한다. 사진 행은 항상 0이다.
5. python scripts/validate_plan.py path/to/plan.json을 실행한다. 이 검사는 파일 경로의 존재·영상 내용·견적·권리·실제 연결을 검증하지 않는다. 해당 검수는 별도 진행한다.

타임라인은 최종 점유 시간 기준으로 빈틈·겹침 없이 기록한다. 디졸브에 쓸 소스 핸들은 따로 확보한다. 전환을 추가했다고 총길이·나레이션이 조용히 줄어들지 않도록 한다.
