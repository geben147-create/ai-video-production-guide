# Cinematic hybrid production

## 최우선 절대 규칙 — 다른 작업보다 먼저 읽고 재확인

> **100장면 중 약 70개만 AI 영상으로 생성한다. 나머지 약 30개는 후반부 중심으로 선별한 이미지에만 사진 모션·합성·편집 효과를 적용한다. 초중반과 후반 핵심 하이라이트는 AI 영상으로 유지한다. 이 배분과 적용 대상은 권고가 아니라 반드시 지킬 제작 조건이다.**

1. **모든 장면을 AI 영상으로 만들거나 모든 이미지를 사진 효과로 처리하지 않는다.** 새 100장면 계획은 영상 70 / 사진 효과 30으로 구체화한다. 사용자가 이미 확정한 기존 72 / 28처럼 다른 구체적 배분이 있으면 그 수와 지시 근거를 기록해 유지한다. 에이전트가 품질·속도·편의를 이유로 78 / 22, 100 / 0 등으로 임의 변경할 수 없다. 이 조건은 사용자가 직접 변경할 때만 바뀐다.
2. **가장 중요한 것은 어떤 이미지에 사진 효과를 줄지 먼저 고르는 것이다.** 후반의 설명·전후 비교·자료 증거·여운 중, 실제 이미지를 확인했을 때 정지된 자료의 탐색·시차·합성만으로 대본을 전달할 수 있는 장면을 선정한다. 후반이라는 이유나 남은 개수를 채우려는 이유만으로 선정하지 않는다. 새로운 인물 행동·사건 전개·물리적 이동이 필요한 장면과 핵심 하이라이트는 제외한다.
3. **사진 효과 전용 허용 목록을 만든다.** 장면 ID, 정확한 이미지 파일, 선정 이유, 기법, 실제 이미지 검수 상태를 기록한다. 목록에 지정된 이미지에만 사진 효과 방식을 적용한다. 목록 밖 장면은 AI 영상이다. 공통 색보정·컷 편집·오디오는 영상에도 적용할 수 있지만 AI 영상을 정지 사진 효과로 대체하지 않는다.
4. **생성·합성 시작 전과 다른 세션에서 재개할 때 반드시 대조한다.** 영상 수 + 사진 수 = 전체 수, 사진 효과 ID 목록 = 실제 photo_motion 행, 초중반 영상 유지, 후반 하이라이트 영상 유지, 이미지 파일·선정 이유·검수 상태를 확인한다. python scripts/validate_plan.py plan.json --execution을 실행하고 배분 요약과 사진 효과 대상 목록을 보여준다. 이것은 실행 전 재확인이며 매번 사용자 승인을 다시 요청하라는 뜻이 아니다.
5. **검사 불일치나 선정되지 않은 이미지는 그대로 실행하지 않는다.** 누락된 분류·이미지 검수·계획을 먼저 보완한다. 유효한 사진 후보가 부족하다고 전체 영상으로 전환하거나 초반 영상을 사진으로 낮추지 않는다. 대본·보호 장면·확정 개수의 충돌을 자체 재배치로 해결할 수 없으면 구체적인 충돌만 사용자에게 알린다. 검수 전 임시 후보는 확정된 효과 대상으로 표시하지 않는다.

역사·도시·건축·과학·경제·인물·제품 등 주제를 바꾸어 사용하는 영화형 혼합 제작 스킬이다. AI 영상과 후반 이미지 편집을 하나의 감정·정보 흐름으로 설계한다. 스킬 편집 요청은 실제 영상 생성이나 기존 제작 재개 지시가 아니다.

## 프로젝트 선택과 배분

1. 현재 대화, 프로젝트 AGENTS.md, 대본·타임라인·기존 작업 기록을 읽는다. 주제, 총길이, 장면 수, 하이라이트, 비용, 도구, 납품 설정을 프로젝트별로 확정한다. 다른 작품의 경로·모델·작업 ID·장면 번호를 가져오지 않는다.
2. 최우선 규칙에 따라 장면 수 기준 약 70:30 배분을 구체적인 개수와 ID 목록으로 고정한다. 사진 모션은 주로 마지막 1/3에서 선별한다. 후반 핵심 행동·스펙터클·해결 하이라이트는 영상으로 보호한다. 정적인 결론은 선별 기준을 충족할 때 사진으로 끝낼 수 있다.
3. 승인된 배분이 있으면 그것을 보존한다. 기존 예시의 100장면은 영상 72 / 사진 28 / 5초 생성 단위 73 / 총 510초다. 이는 모든 프로젝트의 고정 규격이 아니다. 장면 수·영상 시간·최소 생성 단위·실제 제출 횟수는 따로 보고한다. [배분과 프로젝트 예시](references/planning.md)를 읽는다.
4. 장면 배분은 생성 요청 횟수·모델 개수·편집 컷 수와 별개다. 기존 채택 원본은 보존하되 과거의 배분이나 '품질이 더 좋다'는 판단으로 현재의 최우선 규칙을 덮어쓰지 않는다. 하이라이트와 약 70:30 조건이 충돌하면 앞의 충돌 처리 규칙을 따른다.

## 연출과 출처

감정의 중심을 한 문장으로 정하고, 원인 → 시선 이동 → 발견 → 결과 → 여운의 흐름을 대본에 맞춰 만든다. 움직임은 새 정보나 감정을 드러내야 한다. 극적 순간과 읽을 시간을 교대로 배치하고, 역사·사실·인물의 행동을 효과를 위해 바꾸지 않는다.

- 후반 이미지를 설계할 때 [10인 원문·출처 기록](references/sourcebook.md)과 [12개 편집·합성 레시피](references/non-generative-recipes.md)를 읽는다. 실제 발언, 제작자의 타 작품 비평, 스킬의 적용 추론을 명확히 구분한다.
- 장면마다 주요 기법 하나와 필요한 보조 기법을 고른다. 전체에 같은 줌·디졸브·입자를 반복하지 않는다. 전경의 빠른 통과, 중경의 느린 이동, 읽을 수 있는 도착점으로 속도와 깊이를 만들되 준비된 이미지·마스크의 범위를 넘지 않는다.
- **사진 모션은 AI 영상 모델을 호출하지 않는다.** 준비된 이미지·레이어, 키프레임, 합성, 지도·도해, 기존 허가 영상의 부분 루프, 편집과 사운드로 렌더링한다. 별도 새 이미지 생성이 필요하면 이 사용자의 기본인 Codex 내장 image_gen을 사용하고 그 사실을 기록한다. 다른 이미지 생성 도구로 자동 대체하지 않는다. 사용자가 모든 AI 생성도 금지하면 기존 허가 자료와 수작업 요소만 쓴다.
- 평면 사진의 확대를 새로운 공간 이동·인물 행동으로 설명하지 않는다. 마스크와 배경 복원이 없으면 큰 시차를 적용하지 않는다. 강한 카메라 이동을 만들 수 없는 입력은 크롭 공개·매치 컷·음향 전환으로 해결한다.
- 후반 실제 작업 절차와 단어·초 단위 장면 예시는 [후반 제작 매뉴얼](references/postproduction.md)을 따른다. 기법별 숫자는 출발점이며 감독의 공인 공식이나 품질 보장이 아니다.

## 영상 생성·연속성·비용

- 이 사용자의 기본 비용 조건은 무료·0크레딧이다. 모델명과 과거 할인은 범용 기본값으로 고정하지 않는다. 실제 입력·계정·설정의 현재 견적을 검증하고 증거를 저장한다. 프로젝트가 요구하는 이중 견적 등 더 엄격한 조건은 유지한다. 유료 대체·충전·구독 전환을 자동 실행하지 않는다.
- 기존 제출 ID와 상태부터 대조한다. 불확실한 제출은 재조회하여 중복을 막는다. 허용 동시 작업 수는 프로젝트·서비스의 현재 한도 중 낮은 값을 쓴다. 제작 요청이 있을 때만 실행하며 스킬 자체는 미래 작업의 포괄 승인으로 쓰지 않는다.
- 물리적으로 이어지는 actual_end_chain은 앞 클립의 최종 사용 구간이 확정된 뒤 실제 마지막 사용 프레임을 추출한다. 소스, PTS/프레임 번호, 트림, SHA256, 관찰한 방향·속도·광원·시선을 기록하고 다음 입력으로 쓴다. 목표 끝 이미지나 입력 해시 일치는 실제 출력 연결의 증거가 아니다.
- 연속 생성 묶음 안에서는 순서를 지킨다. 서로 독립된 시작 장면만 병렬 서비스 작업으로 처리할 수 있다. 명시적 컷·시대 전환은 억지로 무봉합 연결하지 않는다. 사진↔영상 연결에도 최종 렌더의 실제 사용 프레임을 검토한다.
- 시작·중간·끝 프레임과 정상 속도 재생으로 형태, 움직임, 질감, 이음부를 확인한다. 프롬프트의 속도·경로를 실제 결과의 관찰값으로 복사하지 않는다. 같은 장면의 유사 프롬프트 반복은 명시적 수정 또는 구체적인 검수 실패 사유가 있을 때만 한다.

## 계획·오디오·검수

새 계획은 [plan.schema.json](references/plan.schema.json) 형식으로 저장하고 scripts/validate_plan.py로 구조와 배분을 검사한다. jsonschema 패키지가 필요하다. 기존 계획은 원본을 보존하고 사본에서 이전한다. [범용 100장면 예시](assets/example-plan-100.json)는 자산이나 렌더가 없는 배분 예시다.

장면 계약에는 대본의 정확한 범위, 목적, 모드, 하이라이트, 시간, 소스, 시선 시작·도착, 공개 정보, 레이어, 기법 ID, 소리, 전후 연결, 준비 상태와 검수 결과를 둔다. 사진 효과 행에는 photo_motion_reason, requires_new_action=false, image_review를 추가하고 policy.photo_motion_ids와 일치시킨다. 계획 초안의 미검수 후보와 실제 실행 가능한 이미지를 구분한다. [CSV 양식](assets/shot-contract-template.csv)을 프로젝트에 복사한다.

음성·공간음·행동음·전환음·음악을 별도로 편집한다. 상업 사용 음원, SFX, 영화 참고 청취를 구분한다. URL·라이선스·귀속·확인일·로컬 파일·선택 여부를 기록하고 참고용 음악은 믹스 입력에서 제외한다. 원작 음향을 복제하지 않는다.

최종 검수에서 읽을 수 있는 증거, 마스크 경계, 배경 노출, 시선, 전환 길이와 내레이션 동기, 과도한 고속·흔들림·반복 효과, 음성 명료도, 실제 해상도를 확인한다. 업스케일은 원본 세부 복원이 아니다. 계획 점수와 실제 렌더 평가를 분리한다. 납품 시 적용 기법·출처·변경 이유·검증 결과·남은 제한을 보고한다.
